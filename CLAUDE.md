# Заметки для разработки

- Владелец — не программист, общение на русском, объяснять просто.
- Решения владельца: в справочнике цветов только розничная цена и наличие (закупку считает бухгалтерия, в админке её нет). Цена размера = Σ цена цветка × кол-во + упаковка этого размера (у каждого размера своя), автоматически, и округляется вверх до 5 BYN (177 → 180; решение 2026-10-23, `Pricing::roundUpKop`). Нет цветка → размер скрыт; нет ни одного размера → букет скрыт.
- Свадебные букеты (решение 2026-10-28): у букета с поводом «Для невест» галочка «Только в разделе «Свадебные букеты»» (по умолчанию включена, `weddingOnly`) — его нет на главной, в общем каталоге, поиске и других разделах; прямая ссылка, корзина и sitemap работают (`Catalog::general`).
- Свадебные = предзаказ (решение 2026-11-15): букет с поводом «Для невест» не скрывается, когда цветка нет в наличии (цветы под него заказывают отдельно, `Catalog::preorder`); на сайте пометка «📅 По предзаказу» (карточка, страница букета, корзина) и текст «минимум за неделю до даты, свяжется администратор» (`ShopView::PREORDER_TEXT`); в заказе у букета «По предзаказу». Отдельную функцию предзаказа при заказе (ветка br5qjz) dinx не использует.
- Замены цветов (решение 2026-10-31): задаются в карточке каждого букета для каждого цветка свои (`bouquet_swaps`, блок «🔁 Замены в этом букете»). Цветок закрыли: есть замена в этом букете и она в наличии → букет на сайте по прежней цене, пометка «🔁 Будет замена» в списке букетов, заказе, письме и Telegram (`order_items.swaps`); замены нет → размер/букет скрыт, даже многосоставной. Замены в справочнике «Цветы» — только подсказка (кнопка в букете); при обновлении они перенесены в букеты, кроме монобукетов.
- Размер в см (решение 2026-11-15): у каждого размера букета ширина и высота (`bouquet_sizes.widthCm/heightCm`, 0 — не указано); на сайте плашка «↔ ≈ 35 см ↕ ≈ 40 см» и мелко «примерно, ± 2–3 см» справа внизу на фото букета, меняется с выбранным размером.
- Заказы в админке (решение 2026-11-15): новые сверху, старые внизу (`ORDER BY id DESC`); статус меняется прямо в списке — значок статуса это выпадающий список, сохраняется сразу (`/admin/orders/update` с `ajax=1`); «Выполнен» = сам ставит «оплачен» (решение 2026-11-15).
- Порядок каталога (решение 2026-10-31): Букет дня → ⭐ избранные (`isPinned`) → хиты/эксклюзивы недели → остальные (`Catalog::rank`), внутри группы — ползунки в админке. Новый букет встаёт в конец. Кнопка «🔀 Перемешать остальные» и галочка «каждый день» (настройка `catalog`) мешают только букеты без значков. В списке букетов — «🛒 N за 2 мес.» (заказы).
- Справочник «Цветы» (решение 2026-11-04): цветок, добавленный за последние 7 дней, в админке стоит вверху с пометкой «новый» (кнопка «+ Добавить цветок» ставит строку сверху), потом сам уходит в конец списка; в базе новые всегда в конце `sortOrder`, поэтому в фильтре «Цветок» на сайте они последние (`Catalog::adminFlowerOrder`, `flowerSortOrders`).
- Открытка (решение 2026-11-06): не «в подарок к каждому заказу», а бесплатный доп по желанию (код `card`, цена 0, без «В подарок»); поле «Текст открытки» на букете и в корзине видно, только когда открытка добавлена, без неё текст не сохраняется (`Checkout`). В подарок к каждому букету — только подкормка (`OrderEmail::GIFT`).
- Фото букетов (решение 2026-11-15): админка принимает HEIC с iPhone (переводит в JPEG в браузере, `assets/js/vendor/heic-to.js`, грузится только для HEIC) и фото до 15 МБ (`Uploads::MAX_BYTES`, `php/.user.ini`; больше — уменьшает браузер). Кадр: в карточке букета клик по фото / «✥ кадр» отмечает, где букет (`bouquets.photoFocus`), на сайте `assets/js/focus.js` ставит эту точку в центр каждой рамки.
- «Только из филиала» (решение 2026-11-15): у цветка («есть везде / только из Уручья / Малиновки») и у букета («📍 Где можно заказать»), `onlyShop`. Цветок только в одном филиале и в букете нет замены, которая есть везде → размер только оттуда (`Pricing::sizeOnlyShop`, `Catalog::onlyShop`). На сайте жирная пометка «📍 Только из Уручья» (карточка, страница букета, корзина); в корзине самовывоз только оттуда, доставка по карте «из филиала» (`Delivery::fromShop`, дальний конец города 25 BYN); букеты из разных филиалов одним заказом не оформить. В заказе/письме/Telegram — пометка у букета (`order_items.onlyShop`).
- Новый год (решение 2026-11-12): оформление «Морозная вишня» (`assets/css/newyear.css`, снег, гирлянда, ёлки, сугроб) и сезонный раздел включаются галочками в админке → «Новый год» (настройка `season`, класс `Season`); выключили — сайт снова в основном дизайне. Раздел один (`sections = 'newyear'`), название по дате: до 25.12 (дата в админке) «Зимнее настроение» /catalog/zimnee-nastroenie, с неё «Новый год» /catalog/novyj-god, второй адрес ведёт на действующий. Включён — первым в меню, первым блоком на главной, первой кнопкой над каталогом. Проверить «другой день» локально: переменная `ARTFLORA_TODAY=2026-12-26`.
- «Финансы» (закупка и списание; решение 2026-11-15, `/admin/stock`, право `stock` — только старший администратор): продажи по одной не вносим, пришло по накладным − списали = продали, по магазинам и позициям; закупочная цена живёт только здесь (`stock_*`, `Stock`), справочник «Цветы» по-прежнему только с розницей. Накладная и списание — вручную или фото (накладная, тетрадь с разбивкой по магазинам, лист списания → `Recognize`, Claude API, ключ `anthropic_api_key` в config.php; результат — черновик, сохраняет человек). Цена списания — из последней накладной на дату (`Stock::unitCost`), «продано на» — по рознице цветка. Название строки накладной запоминается (`stock_aliases`). «Вставить из чата» в накладной: JSON-блок {supplier, docDate, totalKop, lines[{name,item,kind,qty,sumKop}], shops{позиция:{код:кол-во}}} — Claude в чате разбирает Excel/фото поставщика и тетрадь, dinx вставляет и сохраняет. Кнопки «+ Доход / − Расход» — цифры из банкинга (`money_entries`, категории `Stock::MONEY_IN/OUT`, в т. ч. Зарплата, Поставщики, Бухгалтерия, Эквайринг, Flowwow (доход), Дивиденды, Корпоративная карточка, Займ СН; обязательное описание «откуда/куда»), блок «Деньги по банку»; у каждой записи «✎ Исправить» (`/admin/stock/money?id=`) и «× Удалить» — и в «Финансах», и в детализации. Дивиденды, корп. карточка, займ СН — не расходы бизнеса, а отдельная графа «Директору» (`Stock::OWNER`, решение 2026-11-15): плитки «Ушло на бизнес», «Бизнес заработал», «Директору», «Осталось». «⧉ Банк из чата» (`/admin/stock/money/import`, `Stock::parseMoneyImport`): блок {"entries":[{date, dir:IN|OUT, cat (ключ MONEY_IN/OUT), sumKop, shop: uruchye|malinovka|"", desc}]} — Claude в чате разбирает скрины банкинга, dinx вставляет → «Проверить» → «Сохранить»; запись с той же датой, направлением, категорией и суммой считается уже внесённой и пропускается. На любую цифру «Финансов» можно нажать — детализация `/admin/stock/detail?m=site|buy|wo|sold|bank|item` (заказы, строки накладных, списания, записи банка, позиции), столбик графика открывает месяц. Под ЕРИП/эквайрингом/безналом подсказка «из них через сайт ≈ X · остальное — другие источники» (оплаченные заказы, `Stock::sitePaid`, `SITE_PAY`); в доходы ничего не прибавляется, двойного счёта нет. Позиции из накладных без цветка из справочника — плашка «нет цены продажи» и форма «Связать» на странице позиции (`Stock::merge`: всё переходит к цветку, название запоминается). Розничная цена берётся на день накладной/списания (`flower_prices`, пишется при сохранении «Цветов» с 15.11.2026, `Stock::retailAt`). Группы (решение 2026-11-15): позиция из накладной/тетради («Альстромерия», «Роза кустовая пионовидная») = несколько цветов сайта (`stock_group_flowers`, `Stock::setGroup`, форма «Сделать группой» на странице позиции): их приход/списание считаются в группе, цена продажи — средняя по цветам на дату (`Stock::groupPrices`). «Вставить из чата» в списании: {date, shop, lines[{name (как в тетради), item (позиция/группа на сайте), qty, shop, reason wilted|broken|supplier|unsold|other, date?, comment?}]}.
- Доставка: покупатель выбирает зону цветной кнопкой или точкой на карте; зоны 6/10/14/18 BYN от ближайшего магазина, за МКАД одна цена (по умолчанию 25 BYN, без доплаты за км, бесплатная доставка там не действует), бесплатно от суммы из админки (сейчас 170 BYN; 200 — только значение по умолчанию), самовывоз −10%; и бесплатная доставка, и скидка считаются со всей корзины, включая допы (решение 2026-11-06).
- Дизайн берём из макетов «Ягодный сад», ничего не перерисовываем с нуля. Без отзывов на сайте. Корзина на телефоне — по шагам.
- Деньги везде в копейках (Int). Цены от клиента не принимаем: сервер пересчитывает (`src/lib/checkout.ts`).
- Чистая логика: `src/lib/pricing.ts`, `delivery.ts`, `slots.ts`, `money.ts` — покрыта тестами `npm test`.

## PHP-версия (решение владельца 2026-10-23)

На хостинге hoster.by («Стартовый+», ISPmanager) нет Node.js, поэтому в папке `php/` делается вторая версия сайта на PHP 8.1 + MySQL, без Composer. Дизайн и логика повторяют версию на Node.js один в один, правила и разделение работы — `php/README.md`. Тесты: `php php/tests/run.php`. Версия на Node.js + готовый сервер (docker-compose.prod.yml, deploy/) — запасной вариант.
