# Сайт «Артфлора»

Интернет-магазин цветов [artflora.by](https://artflora.by): каталог, страница букета, корзина с доставкой и самовывозом, оформление заказа и админка для флористов.

Сделано по макетам «Ягодный сад» (вишня `#7E1F3C`, оливка `#5E6B32`, розовый `#F2C9D4`, белый).

## Что умеет

**Сайт**
- Главная: поводы «Кому дарим?», хиты недели с фильтром по цене, преимущества, подписка на напоминания о датах.
- Каталог: фильтры по поводу, цене, цветку и формату, поиск, пустые состояния.
- Букет: фото, размеры S/M/L со своей ценой, блок «Этот же состав в другом виде», дополнения, текст открытки, примерный расчёт доставки по адресу или району.
- Корзина: на компьютере одной страницей, на телефоне по шагам (Корзина → Доставка → Получатель и оплата). Цены всегда пересчитывает сервер.
- Доставка из ближайшего магазина по зонам 6 / 10 / 14 / 18 BYN, за МКАД +1 BYN за км, бесплатно от 200 BYN, самовывоз −10%.
- Интервалы доставки 10–12 … 18–21, на сегодня — не раньше чем через 2 часа.
- Страница «Заказ принят» и уведомление о заказе в Telegram и письмом на почту (настройка почты — в `.env.example`, адрес получателя — в админке → «Настройки»).

**Админка** (`/admin`, вход по паролю)
- Цветы: только розничная цена и наличие. Меняете цену, и все букеты пересчитываются; справа видно, что изменится на сайте.
- Букеты: состав для каждого размера (цветок × количество) + упаковка, цена считается сама. Нет цветка в наличии → размер или весь букет скрывается и возвращается сам.
- Коллекции: один состав в разных видах (сумка, букет, шляпная коробка, корзина), кнопка «Создать с этим составом».
- Заказы: список, статусы, отметка об оплате.
- Настройки: телефоны и мессенджеры, зоны и цены доставки, магазины, районы, дополнения, реквизиты продавца.

## Как устроено

- [Next.js 15](https://nextjs.org) + TypeScript: сайт и админка в одном приложении.
- PostgreSQL + [Prisma](https://www.prisma.io): схема базы в `prisma/schema.prisma`, деньги хранятся в копейках.
- Расчёты без базы и сети (цены, доставка, интервалы) лежат в `src/lib/pricing.ts`, `delivery.ts`, `slots.ts` и проверяются тестами в `tests/`.
- Доставка считается по району, который покупатель выбирает в корзине (список и точки районов — админка → «Настройки»). Адрес по карте не проверяется: район и адрес сверяют при подтверждении заказа.

## Запуск у себя через Docker (проще всего)

Нужен только [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows, Mac или Linux) и интернет на время первой сборки.

```bash
git clone https://github.com/dinx393/Artflora-site-.git artflora-site
cd artflora-site
docker compose up -d --build
```

Первая сборка занимает несколько минут. Потом откройте:

- сайт: http://localhost:8000
- админка: http://localhost:8000/admin, пароль `artflora`

База стартует пустой: цветы и букеты заводятся в админке (примеры можно включить строкой `SEED_DEMO=1` в `.env`). Всё, что вы поменяете в админке, и заказы сохраняются между перезапусками.

| Что сделать | Команда |
|---|---|
| Остановить | `docker compose down` |
| Запустить снова | `docker compose up -d` |
| Обновить после новых коммитов | `git pull` и `docker compose up -d --build` |
| Посмотреть, что пишет сайт | `docker compose logs -f site` |
| Начать с чистой базы | `docker compose down -v` (удалит заказы и фото!) |

Другой порт или пароль: создайте рядом файл `.env` со строками `SITE_PORT=8080`, `ADMIN_PASSWORD=...`.

### Письма о заказах на почту (Gmail)

1. Заведите ящик для отправки, например artflora.zakaz@gmail.com, и включите в нём двухэтапную аутентификацию.
2. Откройте https://myaccount.google.com/apppasswords, придумайте название («Сайт») и скопируйте пароль из 16 букв.
3. В папке сайта откройте файл `.env` (`nano .env`) и допишите:
   ```
   SMTP_HOST="smtp.gmail.com"
   SMTP_PORT="465"
   SMTP_USER="artflora.zakaz@gmail.com"
   SMTP_PASS="пароль-из-16-букв-без-пробелов"
   ```
4. `docker compose up -d` — сайт перезапустится с почтой.
5. Админка → «Настройки» → «Почта для писем о заказах»: адреса админов через запятую → «Сохранить» → «Отправить пробное письмо».

### Вернуть прошлый дизайн («Ягодный сад»)

19 октября 2026 сайт переведён на дизайн «Артфлора 3». Последняя версия со старым дизайном — коммит `639438a`.
Если новый дизайн нужно временно отменить:

```bash
git checkout 639438a
docker compose up -d --build
```

Вернуться обратно на новый дизайн: `git checkout -` (или `git checkout` той ветки, что была) и снова `docker compose up -d --build`.
Заказы, букеты и фото при этом не теряются: новые поля (цвет букета, «Эксклюзив недели») старая версия просто не показывает.

## Запуск на компьютере разработчика

Нужны Node.js 22 и PostgreSQL 16.

```bash
cp .env.example .env          # впишите пароль админки и SESSION_SECRET
npm install
npx prisma migrate dev        # создаст таблицы
npm run db:seed               # цветы и букеты из макетов
npm run db:demo-catalog       # +140 букетов с artflora.by для проверки большого каталога
npm run dev                   # сайт на http://localhost:3000, админка на /admin
npm test                      # проверка расчётов
```

## Запуск на сервере

```bash
cp .env.example .env          # ADMIN_PASSWORD, SESSION_SECRET, DB_PASSWORD, SITE_URL=https://artflora.by
docker compose up -d --build
```

База на сервере стартует пустой, без примеров (их включает `SEED_DEMO=1`). Открытка и подкормка в подарок добавляются сами.

Чтобы посмотреть сайт с большим каталогом, добавьте 140 букетов с artflora.by (фото грузятся оттуда же):

```bash
docker compose exec site node prisma/demo-catalog.js           # добавить
docker compose exec site node prisma/demo-catalog.js --remove  # убрать
docker compose exec site node prisma/clean-demo.js --yes       # убрать ВСЕ букеты, заказы и напоминания перед запуском
                                                               # (справочник цветов остаётся; с --flowers уберёт и его)
```

Фото букетов сохраняются в томе `uploads`, база — в томе `db`. Делайте их резервные копии.

## Что ещё не подключено

- Оплата картой и ЕРИП: нужен договор с платёжной системой (например bePaid или Assist). Пока заказ оформляется, а оплату флорист отправляет ссылкой.
- Отправка SMS клиенту.
- Рассылка напоминаний о датах: заявки сохраняются в базе (`Reminder`), отправка — следующий шаг.
